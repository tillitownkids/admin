# Object references in the n8n workflows

The admin panel now sends **object sheets** (vehicles, bags, tents and other objects, stored as
"props") alongside character and location sheets. The n8n workflows must pass them on to Magnific;
until they do, objects are ignored and drawn from the prompt text alone.

## What changed in the requests

Both requests gain `references.objects`: object name → Magnific identifier of that object's sheet.
It is always present, and empty (`{}`) when the scene shows no object.

### Storyboard images: `POST /webhook/generate-storyboard`

```json
{
  "scenes": [{
    "id": "<scene uuid>",
    "imagePrompt": "...",
    "references": {
      "characters": { "Jaksh": "<magnific id>", "Tilli": "<magnific id>" },
      "locations":  { "Desert Oasis Campsite": "<magnific id>" },
      "objects":    { "Camping Tent": "<magnific id>", "Family Car": "<magnific id>" }
    }
  }]
}
```

### Video clips: `POST /webhook/generate-video`

```json
{
  "scenes": [{
    "id": "<scene uuid>",
    "shot": 1,
    "duration": 6,
    "videoPrompt": "...",
    "magnific_identifier": "<storyboard image id>",
    "references": {
      "characters": { "Jaksh": "<magnific id>" },
      "locations":  { "Desert Oasis Campsite": "<magnific id>" },
      "objects":    { "Camping Tent": "<magnific id>" }
    }
  }]
}
```

The prompts already name each object exactly as its key, and the video prompt lists them under
"Attachments: … object sheets (Camping Tent)" with the rule "Use the object sheets for object
appearance only."

### Object sheets: `POST /webhook/generate-image`

Object sheets are generated by the same webhook as location sheets, with `name`, `prompt` (a
multi-view sheet prompt built by the app) and `reference_url`. The response must include the image
URL and its Magnific identifier, as for characters; an object sheet without an identifier is
rejected because storyboards and clips need it.

## What n8n needs to do

1. In the storyboard and video workflows, add every value of `references.objects` to the reference
   images sent to Magnific, the same way `references.characters` values are added.
2. Keep within Magnific's limit of reference images per generation. The app sends at most
   **2 objects per scene** (`MAX_SCENE_OBJECTS` in `src/lib/propSheet.ts`), on top of the scene's
   characters and its one location. If the limit is lower, tell the app team to lower that constant;
   if it is higher, it can be raised.
3. If references must be dropped to fit, drop objects before characters and the location.
